# Stera Icons — agent guide

pnpm monorepo for `stera-icons`, a React icon library published to npm.

| Path | What it is |
|------|------------|
| `packages/icons` | The published `stera-icons` package (ESM-only, React peer dep) |
| `apps/docs` | Private Next.js site deployed to [stera.sh](https://stera.sh). Has its own [AGENTS.md](apps/docs/AGENTS.md) |
| `apps/figma-plugin` | Private Figma plugin that exports `packages/icons/icons-export.json`. Has its own [AGENTS.md](apps/figma-plugin/AGENTS.md) |

Human contributor docs live in [CONTRIBUTING.md](CONTRIBUTING.md). Read it before adding or changing icons.

## Commands

Use **pnpm** only (never npm or yarn). Node >= 22; `.nvmrc` pins 24. Run from the repo root.

| Command | What it does |
|---------|--------------|
| `pnpm install` | Install dependencies |
| `pnpm build` | Full build of `stera-icons` (tsup + icons + declarations) |
| `pnpm build:icons` | Regenerate icon components, metadata and declarations only |
| `pnpm --filter stera-icons exec vitest run` | Run tests once. `pnpm test` starts watch mode in a terminal |
| `pnpm lint` | ESLint on `packages/icons/src` |
| `pnpm dev:docs` | Run the docs site. Requires `pnpm build` first |
| `pnpm build:plugin` | Build the Figma exporter plugin into `apps/figma-plugin/dist` |
| `pnpm dev:plugin` | Rebuild the Figma plugin on change |

Do not run a whole-project `tsc` in `packages/icons`: it runs out of memory on the generated icon files. `pnpm build` is the type check.

## Source vs. generated files

Never hand-edit a generated file. Change the source or the generator, then rebuild.

| File | Kind | In git |
|------|------|--------|
| `packages/icons/icons-export.json` | **Source.** Figma export; the only source of icon artwork, names, tags and categories | yes |
| `packages/icons/icon-aliases.json` | **Source.** Deprecated aliases that keep the old names of renamed icons working | yes |
| `packages/icons/categories.json` | **Source.** The closed list of icon categories. The build rejects any category on an icon that is not defined here | yes |
| `packages/icons/src/{IconBase,DynamicIcon}.tsx`, `src/{base,dynamic,types,utils}.ts`, `src/__tests__/` | **Source** | yes |
| `packages/icons/scripts/` | **Source.** The build pipeline | yes |
| `packages/icons/src/icons/*.tsx` | Generated | yes |
| `packages/icons/src/{index,dynamic-variants,dynamicIconImports}.ts` | Generated | yes |
| `packages/icons/dist/icons.meta.json` | Generated. Holds per-icon version history; **must be committed** | yes |
| Rest of `packages/icons/dist/` | Generated | no |
| `apps/docs/data/` | Generated by `apps/docs/scripts/generate-icons.mjs` | no |
| `apps/figma-plugin/dist/` | Generated by `apps/figma-plugin/scripts/build.mjs` | no |

Things to know about the build:

- `icons-export.json` is about 10 MB. Never read it whole; query it with `node -e` or `jq`.
- `build-icons.js` deletes and regenerates `src/icons/` on every run, and rewrites the `exports` field of `packages/icons/package.json`.
- The `.d.ts` files in `dist/esm` are written from templates in `scripts/generate-declarations.js`, not emitted from source. If you change a public type in `src/`, update the matching template.
- After a build, `git status` should show only files you meant to change.

## Adding or changing icons

Order matters. The changeset must exist before the build, because the build reads it to stamp `versionAdded` on new icons.

1. `pnpm changeset`
2. `node packages/icons/scripts/hash-versioning.js info` — confirm `Has pending changesets: true`
3. Update `packages/icons/icons-export.json`. Export it from Figma with the plugin in `apps/figma-plugin` (see its [README](apps/figma-plugin/README.md)) and copy the download over the committed file
4. `pnpm build:icons`
5. Update the hand-written docs (see below)
6. `pnpm --filter stera-icons exec vitest run`
7. Commit everything, including the generated `src/` files and `packages/icons/dist/icons.meta.json`

### Renaming an icon

To keep the old name working for a grace period, add it to `packages/icons/icon-aliases.json` before the build:

```json
"old-name": { "to": "new-name", "since": "8.8.0", "removeIn": "9.0.0" }
```

- `since` is the version the rename ships in. `removeIn` is the next major.
- The build re-exports the new icon under every old export name (marked `@deprecated`), writes `stera-icons/icons/<OldName>` files, and makes `DynamicIcon` accept the old name. Aliases are left out of `icons.meta.json`, `iconNames` and the docs site.
- The build fails once the version being built reaches `removeIn`. Delete the entry then, and list the removed name in that release's changeset.

### Docs to update after an icon change

Most icon docs regenerate on their own: the `@tags` JSDoc in `index.d.ts`, `dist/icons.meta.json`, the icon index at `stera.sh/llms-full.txt`, and every count shown on the docs site. Only these are hand-written:

| When | Update |
|------|--------|
| Icons added or removed | `README.md` stats table: `Icons` and `Total variants` (icons × 6) |
| Count crosses a hundred (e.g. 900) | The `800+` figure in `packages/icons/llms.txt` and `packages/icons/README.md` |
| An icon used as a doc example is renamed or removed | Every mention in `packages/icons/llms.txt`, `packages/icons/README.md` and `apps/docs/components/docs-content.tsx` |
| An icon is added whose name the docs say does not exist (`SiClose`, `SiEdit`, `SiGear`, `SiCog`) | The "do not guess" examples in the same files, and `DOCUMENTED_AS_MISSING` in the test |
| Any rename or removal | A migration note in the changeset body (old name → new name). A rename that ships with an alias is `minor`; a removal, or a rename without one, is `major` |

`packages/icons/src/__tests__/docs.test.ts` enforces the first four rows, so a failing test there means a doc is stale, not that the test is wrong.

## Versioning and release

| Bump | When |
|------|------|
| `patch` | Bug fixes, small refinements to existing icons |
| `minor` | New icons, new backwards-compatible features, icon renames that keep the old name as an alias |
| `major` | Icon removals, renames without an alias, removing an expired alias, and any other breaking change |

- Any change that affects what ships to npm (`src/`, `scripts/`, `README.md`, `llms.txt` in `packages/icons`) needs a changeset. Changes to `apps/docs` and `apps/figma-plugin` do not.
- Releases are automated by `.github/workflows/release.yml`. **Never run `pnpm changeset version`, `pnpm version-packages`, `pnpm release` or `npm publish`.**

## Docs to update after an API change

When the public API, requirements or behavior of `stera-icons` changes, update all of:

- `packages/icons/llms.txt` — LLM usage guide. Ships to npm and is served at `stera.sh/llms.txt`
- `packages/icons/README.md` — ships to npm
- `apps/docs/components/docs-content.tsx` — the docs page on stera.sh
- `packages/icons/src/types.ts` JSDoc and the templates in `scripts/generate-declarations.js`

## Conventions

- Conventional commits: `feat:`, `fix:`, `chore:`, `docs:`.
- Do not add AI attribution or `Co-Authored-By` trailers to commits or pull requests.
- To render icons in an app or gallery, use the `stera-icons/dynamic-variants` components with `dist/icons.meta.json`, as `apps/docs/scripts/generate-icons.mjs` does. Do not render from the raw SVG strings in `icons-export.json`.
