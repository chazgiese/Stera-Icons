# Figma plugin notes

Repo-wide rules are in the root [AGENTS.md](../../AGENTS.md). Usage is described in [README.md](README.md).

- This is the Figma plugin that produces `packages/icons/icons-export.json`. It is private and never published.
- Source files are `src/code.ts` (runs in the Figma sandbox) and `src/ui.html` (the plugin UI). `dist/` is generated by `scripts/build.mjs` and gitignored; never edit it.
- Build with `pnpm build:plugin` from the repo root, or `pnpm dev:plugin` to rebuild on change. CI runs `pnpm --filter @stera/figma-plugin typecheck`, `lint` and `build`.
- The exported JSON is the contract with the `stera-icons` build (`packages/icons/scripts/build-icons.js`). Do not change its key order (`id`, `name`, `tags`, `categories`, `variants`), sorting, SVG normalization or hashing without updating that build and the README here. Each field has one job: `id` (the Figma component set key) is the icon's identity and drives rename detection and alias generation, `hash` drives artwork change detection in `dist/icons.meta.json`, and `name` is the public API.
- Every icon must be a component set; a pre-check rejects loose components, because only a set has a key to export as `id`.
- `src/code.ts` is a global script with no imports or exports. Do not enable `isolatedModules` in `tsconfig.json`; tsc rejects global scripts under it.
- The plugin cannot write to disk. Exports are downloaded by the browser and copied to `packages/icons/icons-export.json` by hand.
- This package is in the changeset `ignore` list. Never create a changeset for it: `hash-versioning.js` reads pending changesets to stamp `versionAdded` on icons.
- Figma Desktop loads the plugin through `Plugins` → `Development` → `Import plugin from manifest...` → `apps/figma-plugin/manifest.json`. The manifest's `main` and `ui` point into `dist/`.
